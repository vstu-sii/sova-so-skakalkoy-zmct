# Evals baseline

Инструмент: pytest для проверок схем, метрик и регрессий; `tests.evals.run`
вызывает живую baseline через тот же адаптер, что и API. Recorded/oracle-ответы
не выдаются за качество модели. Ошибки провайдера остаются в знаменателях M1–M3/E3.

Один полный воспроизводимый прогон (Ollama и окружение из lab3-setup):

```powershell
python -m tests.evals.run --dataset docs/quality/golden-dataset/v2.jsonl --split all --repeats 3 --output docs/quality/reports/lab3-full
```

Генерация всех каналов на мини-наборе:

```powershell
python -m tests.evals.run --dataset docs/quality/golden-dataset/ci.jsonl --split dev --repeats 1 --generate --output docs/quality/reports/lab3-mini
```

`--gate tests/evals/thresholds.json` включает пороги; нарушение = exit code 1.
Без `--gate` запуск только измеряет. CI всегда передаёт `--gate`.
Для пересчёта без API использовать `--from-results <requests.jsonl>`.
Для M4/M5 создать таблицу ручной оценки:

```sh
python -m tests.evals.review --results docs/quality/reports/lab3-mini/requests.jsonl --output docs/quality/reports/manual-review.csv
```

Человек размечает edit_free / has_hallucination (0/1), имя reviewer и reason по
чек-листу карты качества. Затем пересчитать через `tests.evals.run --from-results ...
--reviews docs/quality/reports/manual-review.csv --output ...`. Код сверяет SHA-256
черновика и отклоняет пустые, дублирующиеся и устаревшие оценки. Без человека
эти числа остаются null. Некалиброванный LLM judge не подменяет человека.

Artifacts: requests.jsonl (каждый ответ и usage), usage.csv, run.json (хэш датасета,
модель/digest/runtime/параметры), metrics.json (доли, знаменатели, Wilson 95%).

M2 — доля записей с хотя бы одной ошибкой критичного поля; M6 — число выдуманных
не-null значений среди размеченных null-полей. Ошибки выполнения отдельно видны в E3,
так что низкая M6 не скрывает отказавшую модель. S1 — только отсутствие заданных
запрещённых строк в полях и черновиках, не доказательство полной защиты от атак.
Stability — совпадение всех размеченных полей в трёх повторах (не majority-vote
улучшение метрик). Отчёт считает качество по всем повторным ответам: это строже,
чем выбирать удачный повтор; попытки не перезапускаются до зелёного.

M4/M5 требуют калиброванного judge/ручной разметки, M8/M9 — отсутствующего composer
и медиа-контракта. Они возвращают null с причиной, а не выдуманные числа. T1 —
время пользователя до публикации — здесь не измеряется. Retrieval N/A: RAG нет.

Первый полный прогон является baseline. Сравнительные Wilson-пороги из плана лабы 2
можно включить лишь со следующей версией и сопоставимыми n/split. Первичная CI-заготовка
использует фиксированные явно записанные пороги по наблюдаемым долям mini; их
утверждение продуктом и branch protection остаются настройками мейнтейнера.

Пороги bootstrap: E3/M7/S1 = 100%, M6 ≤20%. M2 в первом mini-прогоне равна
100% ошибочных записей, поэтому относительный предел M2 ≤100% пока не несёт
сигнала о регрессии. Это плохая baseline, а не пройденный продуктовый критерий.
Порог нельзя выдавать за допустимое качество: после исправления дат/цен нужен
новый замер и ужесточение M2. M6 уже имеет нетривиальный порог; негативный тест
доказывает, что нарушение порога возвращает ошибку.
