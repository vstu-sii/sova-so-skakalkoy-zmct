Инструкции запуска и границы реализации — [lab3-setup](../docs/experiments/lab3-setup.md).
Текст ниже сохраняет исходные договорённости лабы 2.

[openapi.yaml](openapi.yaml) — OpenAPI 3.1 в JSON-представлении. JSON является допустимым YAML 1.2; файл можно открывать в Swagger Editor и импортировать как OpenAPI. Такой синтаксис выбран для проверки стандартной библиотекой Python без установки зависимостей. Контракт предложен для согласования с Delivery, сервер ещё не написан.

## Последовательность

1. `POST /v1/ai/extractions` создаёт draft v1 и кандидата. `needs_clarification` означает, что нужен исправленный/дополненный ввод. Для initial draft исправленный ввод отправляется новым extraction; неиспользованные draft удаляются по политике хранения.
2. `POST /v1/events/{event_id}/confirm` подтверждает кандидата при совпадении версии, создаёт v2.
3. `POST /v1/events/{event_id}/ai/generations` принимает v2 и список каналов; сервер читает карточку сам.
4. Для переноса — `POST /v1/events/{event_id}/ai/patches` с текущей версией. Получить кандидата, просмотреть изменения, подтвердить; старая карточка до этого действует.
5. `GET /v1/events/{event_id}` читает текущую версию. При 409 перечитать карточку и повторно подготовить правку, не применять старый кандидат вслепую.

Уточнение после patch: отправить дополненный текст новым запросом patch на актуальной версии. Для ручного режима Delivery предлагает заполнить сведения и сформировать полный уточнённый текст; пользователь повторяет extraction/patch после восстановления модели. Без модели новое событие остаётся локальной ручной формой Delivery; контракт не выдаёт его за подтверждённое AI-событие. Уже подтверждённые карточки можно рендерить через template-генерацию без модели.

Все POST требуют `Idempotency-Key`, все методы — bearer-аутентификацию. Чужой ресурс возвращает 404. Примеры в спецификации синтетические, не реальный API-лог. Внутри каждого endpoint примеры самостоятельные; UUID повторяются ради краткости.

## Что сервер проверяет сверх схемы

- IANA timezone, реальный календарь, относительные даты, отсутствие конфликтов.
- Полноту карточки перед подтверждением, цену и скидку, порядок дат.
- Тип `Change.value` по field, допустимость set/clear, отсутствие повторов, evidence.
- Владение, base/expected_version, атомарность, истечение кандидата.
- Одно содержимое на каждую запрошенную площадку, точные факты при рендере.
- Атомарный резерв бюджета и idempotency, фактический usage всех попыток.

Публичная схема ответа включает серверные metadata. Не отправлять её целиком модели: адаптер формирует strict-проекцию только для Event/Change/Issue или текстового фрагмента генерации. Не все ограничения OpenAPI поддерживаются провайдером; оставшиеся ограничения проверяет сервер. Semantic validation не заменяется структурированным выводом.
