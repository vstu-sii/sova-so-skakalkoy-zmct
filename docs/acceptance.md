## 1. Правила приёмки

**Когда:** раз в 2 недели, в четверг, 30–45 минут. Даты: 12.11 (приёмка 0, вход спринта), 26.11 (приёмка 1), 10.12 (приёмка 2, перед показом на Demo Day).

**Между приёмками:** контрольная точка burndown по четвергам без приёмки — 03.12: владельцы обновляют `tasks.csv`, Product записывает точку и при отклонении больше 15 ч принимает решение по резке (`docs/mvp-scope.md` §4).

**Почему не еженедельно (решение приёмки 1, 27.11):** недельные приёмки 18.11 и 25.11 не проводились — инкременты команда вливает в `main` пакетами раз в 1–2 недели (PR #16, #18, #19 влиты одним днём, 26.11), и недельная приёмка принимала бы пустоту. До 27.11 правило было «каждую среду: 18.11, 25.11, 02.12, 09.12» — см. историю этого файла.

**Кто:** принимает Product / VO; владелец задачи показывает; смежная роль — ревьюер (G4 из `docs/quality/dod.md`).

**Что принимаем:** только задачи со статусом `doing`/`done` в `docs/sprint/tasks.csv`, работа по которым влита в `main`. Ветка без merge показывается, но не принимается.

**DoD инкремента** — задача принята, если выполнено всё:

| # | Критерий | Как проверить |
|---|---|---|
| I1 | Работает на стенде, а не только локально | Показ на https://tanya-lab.88-87-92-145.sslip.io/ или ссылка на прогон CI |
| I2 | Соответствует критерию готовности пункта скоупа | Колонка «Критерий готовности» в `docs/mvp-scope.md` §2 |
| I3 | Тест или eval, который упадёт при регрессии | Ссылка на тест / job в CI |
| I4 | Нет демо-данных и заглушек под видом результата | Ответ `not_implemented`/`TODO`/константа ≠ успех |
| I5 | Тестовый канал помечен как тестовый | Интерфейс и документация |

**Решения по задаче:** ✅ принято → `done` в `tasks.csv` · ⚠️ принято с отклонением → `done` + новая задача на отклонение · ❌ не принято → обратно в `doing`, остаток по оценке владельца.

**Отклонение** записывается строкой «что не так → задача ID → владелец → срок». Без ID задачи отклонение не считается записанным.
