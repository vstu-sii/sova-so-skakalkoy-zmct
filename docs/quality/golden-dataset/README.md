# Golden dataset v2

`v2.jsonl`: 53 примера = 35 исходных v1 + 9 adversarial + 6 новых регрессий
по отчёту лабы 1 + 3 случая из фактического прогона локальной baseline (версия 2.1).
`ci.jsonl`: 6 фиксированных dev-примеров, включая отдельную копию synthetic attack;
это наблюдаемый regression-набор, не независимый test holdout.

Источники лабы 2: `upstream/feature/quality_lab2:docs/golden-dataset/`.
Исходные `expected` сохранены в `legacy_expected` для аудита; `assert_fields`
определяет, что действительно размечено для public Event из API лабы 2.
Поля description и свободный registration у старых примеров отсутствуют в разметке,
поэтому не объявляются оценёнными. title сравнивается только после case/whitespace
normalization, без семантического угадывания синонимов.

Миграция цен: general → price, returning/early_bird → price_discount. Донаты,
валюты кроме RUB и несколько ставок одной аудитории исключают **обе** ценовые
метрики записи; остальные поля записи остаются в оценке. Неподдерживаемые поля
duration_min, format, speaker, registration_url и media явно перечислены.
M1/M3 относятся к этой проекции, а не ко всей старой схеме. Формат, медиа и
пригодность к публикации не получают фиктивный 100%.

Новые случаи v2-001…006 основаны на ошибках из `docs/experiments/lab1.md`:
конфликт даты и дня недели; потеря имени площадки/этажа; false-fill; две цены;
prompt injection. Все новые тексты синтетические, без реальных телефонов клиентов.
Для `gd-live-001…003` указаны source_id, путь к реальному ответу и его SHA-256.
Это новые варианты формулировок для ошибок month-only, серии встреч и неизвестного
места/времени. Эталоны исходных примеров не менялись после просмотра модели.

Проверка: `python -m pytest tests/evals/test_dataset.py -q`.
Негативный тест намеренно повреждает запись и убеждается, что валидатор её отклоняет.
Эталоны не исправляются под ответы модели. При изменении ожиданий нужен новый
dataset_version и причина в CHANGELOG; test split не участвует в настройке промптов.
