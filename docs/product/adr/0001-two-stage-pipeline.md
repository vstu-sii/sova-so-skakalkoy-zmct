# ADR-0001. Two-stage pipeline: извлечение через function calling, генерация под каждую площадку

Статус: принято
Дата: 2026-10-15
Автор: AI Engineer
Касается: пайплайн обработки анонса, контракт между шагами, сборка страницы

Основание и расчёты: `docs/research.md`, разделы 2.2–3.3.

## Контекст

На входе один свободный текст эксперта. На выходе нужны три материала — пост во ВКонтакте, письмо, страница мероприятия — и набор структурированных значений: дата, время, место, цена. Значения обязаны совпадать во всех трёх, иначе возникает рассинхронизация, то есть главная подтверждённая боль из PRD.

Технически можно попросить модель сразу выдать готовый материал под каждую площадку, не выделяя поля отдельно.

## Решение

Обработка разделена на два шага.

Первый шаг извлекает поля через function calling со схемой: `date_start`, `time_start`, `venue`, `price`, `price_discount`, `title`. Результат валидируется по схеме до того, как попадёт дальше. Если значения во входе нет, модель возвращает `null`, а не догадку.

Второй шаг получает исходный текст и уже извлечённые поля и генерирует материал под конкретную площадку по её промпту.

Страница мероприятия собирается из той же структуры, что и посты, а не из их текстов.

Конкретная модель фиксируется в `docs/research.md` и может меняться без нового ADR, пока сохраняется двухшаговая структура. Исключение — переход на российского провайдера ради 152-ФЗ: он добавляет в систему путь fallback, то есть меняет структуру, и требует отдельного решения.

## Альтернативы

**Один большой промпт «сделай всё».** Отклонено: модель путает извлечение и генерацию, растёт риск ошибки в дате и цене. Отдельно важно, что точность критичных полей невозможно измерить, когда значение растворено в тексте поста, — вся система метрик из `docs/quality/success-criteria.md` становится неприменимой.

**Агент с инструментами.** Отклонено по бюджету: два-три вызова модели дают 15–30 ₽ против лимита 10 ₽ на комплект.

**RAG по базе прошлых анонсов.** Отклонено для MVP: каждый анонс уникален, усложнение не окупается.

**Дообучение модели.** Отклонено для MVP: дорого, промпт-инжиниринг даёт основную часть результата.

**Извлечение регулярными выражениями без модели.** Остаётся открытым: формулировки в анонсах разнородны, объём правил заранее неизвестен. Проверяется на эталонном датасете; если правил хватит, первый шаг упростится без изменения структуры.

## Цена решения

**Два вызова вместо одного.** Стоимость и задержка растут примерно вдвое. При текущих расчётах запас по бюджету большой, но каждая перегенерация при правке платится дважды. Частичная митигация — кэш первого шага: если текст не менялся, повторное извлечение не выполняется.

**Зависимость от зарубежного провайдера.** Данные уходят за рубеж, что создаёт юридический риск для клиентов с требованиями 152-ФЗ. Митигация — fallback на российскую модель, но это отдельный путь в системе, который надо писать и поддерживать. Срок — до первого клиента с жёсткими требованиями.

**Контракт между шагами.** Схема полей становится общей зависимостью извлечения, генерации, страницы и эталонного датасета. Любое её изменение затрагивает четыре места сразу и обесценивает уже размеченные примеры.

**Ошибка извлечения распространяется дальше.** Неверно распознанная дата попадёт во все три материала одинаково неверно. Компенсируется предпросмотром, где эксперт подтверждает поля до публикации.

**Заголовок генерируется, а не извлекается.** Риск выдуманного заголовка. Митигация — показывать его как редактируемое поле, эксперт подтверждает перед публикацией. Срок — MVP.

**Нечёткие адреса вида «ориентировочно центр».** Приводят к рассинхронизации и приходу участников не по адресу. Митигация — валидация через геокодер и запрос уточнения, если место не определено. Срок — спринт 2.

**Потеря льготной цены при правках.** Ошибка в цене на одной из площадок. Митигация — хранить исходную структуру и сливать с правкой, а не перезаписывать целиком. Срок — спринт 2.

**Конфликт даты и дня недели** в формулировках вроде «25 ноября, вторник». Ведёт к публикации неверной даты. Митигация — если день недели не совпадает, вернуть `null` и запросить подтверждение. Срок — спринт 2.

Суммарно около шести инженерных задач на два спринта. У каждого долга есть план погашения.

## Последствия

- Схема полей фиксируется в `docs/quality/success-criteria.md` и меняется только договорённостью команды.
- В UC-01 обязателен шаг, где система показывает извлечённые значения, а эксперт их подтверждает.
- Метрики точности считаются по полям, а не по текстам материалов.
- Доказательства работоспособности подхода — `docs/experiments/lab1.md`.
