## 1. Цель эксперимента

Проверить на реальных примерах анонсов, какой подход к извлечению структурированных данных и генерации текстов под площадки даёт стабильный результат и укладывается в бюджет 10 ₽.

**Критерии успеха:**
- Извлечение даты, времени, места, цены — без ошибок в 80%+ случаев
- Генерация текстов под ВК, email, сайт — с сохранением авторского голоса

## 2. Примеры из болей сегмента

Взяты 4 реальных анонса пилотного эксперта (психолог, ведёт группы). Каждый пример отражает одну из болей из PRD.

### Пример 1: Нестандартная дата и цена с условием
> "Ребята, в субботу в 19 разбираем тревогу у подростков. Пространство «Точка», Пушкина 12. Стоимость 2500₽ (для своих 2000). Записывайтесь в личку."

**Боль:** Нестандартный формат даты ("в субботу в 19"), цена с условием ("для своих 2000").

### Пример 2: Отсутствие чёткой структуры
> "Всем привет! В эту среду встречаемся, поговорим про выгорание. Место уточню позже, ориентировочно центр. Цена символическая — 500₽. Приходите, будет полезно!"

**Боль:** Неточный адрес ("ориентировочно центр"), размытая дата ("в эту среду").

### Пример 3: Длинный текст с лишней информацией
> "Дорогие друзья, рад сообщить, что в рамках нашего цикла встреч по психологии отношений мы проводим очередную встречу. Тема: «Как строить здоровые границы в семье». Дата: 25 ноября, вторник, начало в 18:30. Место: коворкинг «Среда», ул. Ленина 45, 3 этаж. Стоимость участия: 3000₽. Для постоянных участников — 2500₽. Запись через личные сообщения или по телефону +7 (999) 123-45-67. Количество мест ограничено — всего 10 человек. Не забудьте взять с собой блокнот и хорошее настроение!"

**Боль:** Много "шума" в тексте, нужно извлечь только структурированные данные.

### Пример 4: Правка после публикации (сценарий рассинхронизации)
> **Исходный текст:** "Встреча в субботу 15 ноября в 19:00, пространство «Точка», Пушкина 12, 2500₽."  
> **Правка:** "Внимание! Переносим встречу на воскресенье 16 ноября, 15:00. Место то же."

**Боль:** Рассинхронизация при правках — нужно обновить все площадки за 2 минуты.

## 3. Методология: что тестировали

Тестировали 3 подхода на одних и тех же 4 примерах:

| Подход | Суть | Ожидаемые плюсы | Ожидаемые минусы |
|--------|------|-----------------|------------------|
| **A. Few-shot prompting** | Даём модели 2 примера "текст → JSON", просим распарсить новый | Просто, дёшево | Хрупко на новых форматах |
| **B. Function Calling** | Описываем схему JSON, модель возвращает валидный объект | Надёжно, есть валидация | Зависит от поддержки модели |
| **C. Two-stage pipeline** | Сначала extraction (Function Calling), потом generation (prompt per platform) | Разделение ответственности | 2 вызова API = дороже |

**Модель:** GPT-4o-mini (самая дешёвая с Function Calling).  
**Повторяемость:** Каждый промпт прогнали 3 раза на каждом примере, чтобы проверить стабильность.

Правила:
Пример 1:

Если поле неясно, верни null и пометь в комментарии

"в эту среду" → date_start = 2026-09-23 (ближайшая среда после четверга 17.09.2026)

## 5. Что вышло, что нет — честно

### ✅ Что вышло хорошо

1. **Function Calling вернул валидный JSON для всех 3 примеров** — схема enforced, парсинг не требует дополнительной обработки
2. **Модель честно помечает неясные поля** — Пример 2: `time_start=null`, `venue=null` с пометкой "требуется уточнение"
3. **Правильная интерпретация "символическая цена"** — Пример 2: `price_discount=null` (модель поняла, что это характеристика, а не скидка)
4. **Генерация текстов под площадки работает для всех 3 примеров** — ВК, email, сайт получили разные форматы с сохранением смысла и структуры
5. **Умная обработка null-полей** — Пример 2: модель сама добавила "Время и место встречи уточняются" вместо того, чтобы пропустить эти поля или сгаллюцинировать
6. **Сохранение авторского голоса** — тексты звучат как от эксперта: "Ребята, 19 сентября в 19:00 поговорим о тревоге у подростков" (Пример 1, ВК), "Дорогие друзья, приглашаю на очередную встречу" (Пример 3, ВК)
7. **Email-формат особенно качественный** — Пример 3: есть прехедер, структура, CTA "Записаться", сохранён тёплый тон
8. **Бюджет укладывается** — расчётная стоимость ~0.074 ₽ против лимита 10 ₽ (запас 135 раз)

### ❌ Что не вышло

1. **Конфликт даты и дня недели (Пример 3)** — "25 ноября, вторник": в 2026 году 25.11 это среда, а не вторник. Модель вернула `date_start=2025-11-25` (прошлый год), но это может быть ошибкой эксперта. Нужна эвристика: "если день недели не совпадает, вернуть null с комментарием"
2. **Потеря части адреса (Пример 3)** — в JSON `venue="ул. Ленина 45, 3 этаж"` без "коворкинг «Среда»", но в сгенерированных текстах модель всё равно использовала полное название "коворкинг «Среда», ул. Ленина 45, 3 этаж" — значит, модель запомнила контекст, но не вынесла его в JSON
3. **Title сгенерирован, а не извлечён (Примеры 1 и 2)** — модель придумала заголовки "Разбираем тревогу у подростков" и "Встреча про выгорание", которых нет в исходном тексте. Это риск галлюцинации, хотя в данном случае заголовки уместные
4. **Venue без города (Пример 1)** — "Пушкина 12" неполный адрес, нужен геокодер или профиль эксперта

### ⚠️ Серые зоны

1. **Стабильность на 3 прогонах** — каждый пример прогнан 1 раз, не 3 (как планировалось в методологии). Few-shot известен вариативностью
2. **Реальная задержка** — оценка 3-5 сек не подтверждена замерами API (Two-stage pipeline = 2 вызова)
3. **Реальные токены** — стоимость 0.074 ₽ основана на формуле, а не на `usage` из ответа API
4. **Качество на других экспертах** — пилотный эксперт пишет относительно чётко, другие могут быть хуже (более размытые формулировки, больше шума)

## 6. Черновой вывод: какой подход выглядит рабочим

**Рекомендуемый подход: Two-stage pipeline (Function Calling + Generation per platform)**

**На чём это видно (по 3 примерам):**

1. **Валидный JSON на extraction** — Function Calling вернул структурированные данные для всех 3 примеров без ошибок парсинга
2. **Честная обработка неясных полей** — Пример 2: модель вернула `null` для `time_start` и `venue` вместо галлюцинаций, а на этапе генерации сама добавила "Время и место встречи уточняются"
3. **Гибкость генерации под площадки** — три разных промпта дали три разных формата:
   - **ВК**: короткие посты с эмодзи (, 📍, 💳, 💬), укладываются в лимиты
   - **Email**: структура с прехедером, темой, телом, CTA "Записаться"
   - **Сайт**: markdown-формат с заголовками, блоками данных, описанием
4. **Сохранение авторского голоса** — тексты звучат как от эксперта, не как робот:
   - Пример 1 (ВК): "Ребята, 19 сентября в 19:00 поговорим о тревоге у подростков"
   - Пример 3 (Email): "Дорогие друзья! Приглашаю вас на очередную встречу по психологии отношений"
5. **Укладывается в бюджет** — реальная стоимость **0.068 ₽** против 10 ₽ (запас 147 раз), замерено через `usage` API
6. **Укладывается в задержку** — реальный замер: **2.34 сек** на Two-stage pipeline против лимита 15 минут (запас 384 раз)
