## 1. Что показываем на Demo Day

Один сквозной сценарий на стенде, в таком порядке:

1. Эксперт вставляет текст анонса и указывает дату → видит карточку «дата / время / место / цена» с исходными фрагментами, правит неверное, подтверждает.
2. Система собирает три черновика: пост ВК, письмо, страница мероприятия. Эксперт публикует.
3. Участник открывает страницу по постоянной ссылке и записывается. Эксперт видит заявку в кабинете.
4. **Главное:** эксперт меняет время → страница и пост ВК обновлены, подписчикам ушло письмо-уведомление, итоговый экран показывает статус каждого канала. Цель — не больше 2 минут.

Шаг 4 важнее шагов 1–3: это единственная боль, подтверждённая двумя респондентами независимо (PRD, боль 2).

## 3. Вырезано — с причинами

Вырезать фичу — решение, а не поражение. Каждый пункт можно вернуть после Demo Day только через новый UC или его версию.

| # | Что вырезано | Причина | Что вместо |
|---|---|---|---|
| C1 | **UC-03 «Исправить текст после публикации»** целиком | Правило роадмапа §4: при нехватке спринтов UC-03 уходит первым. Подтверждён одним респондентом (Алла). Требует версионирования исходника и защиты ручных override — оценка 6–10 ч (iteration-notes, P2), спринт её не вмещает | Самая опасная часть UC-03 — правка даты/времени/места/цены — покрыта UC-02 (S10). Опечатку в тексте эксперт правит в ВК вручную |
| C2 | Загрузка нескольких картинок и порядок карусели (UC-01 шаг 5) | 8–14 ч; M9 не измеряется (API не принимает медиа); боль с картинками в интервью не звучала | Страница и пост с нейтральной обложкой шаблона |
| C3 | Страница из библиотеки блоков | Нет page-composer с блоками; M8 не измеряется | Один фиксированный шаблон страницы |
| C4 | Промежуток дат (многодневные события, серии) | Серии уже в не-скоупе роадмапа; date_start = 77.1%, ошибки дат — главный риск, промежуток его удваивает | Только один день + время начала |
| C5 | Обязательное отдельное поле заголовка | Разрыв 1 лабы 3 решён правкой UC: эксперт пишет «как в личный канал», заголовок извлекается (title = 65.9%, поэтому — с правкой в карточке) | S3 |
| C6 | Публикация в боевое сообщество ВК эксперта и на реальную базу подписчиков | S1 = 53.3% в lab3; токен/модерация приложения ВК; публикация от имени эксперта без доказанной безопасности недопустима | Тестовое сообщество и тестовый SMTP (S6); статус «тестовый канал» в интерфейсе |
| C7 | Предупреждение «до мероприятия меньше суток» (UC-02 Э3) | Удобство, не влияет на корректность | Перенос в бэклог после Demo Day |
| C8 | Письмо эксперту о каждой новой заявке | Отдельная интеграция с рассылкой; в интервью не запрашивалось | Список заявок в кабинете (S9) |
| C9 | Автоматическая оценка M4/M5 LLM-судьёй | Судья не откалиброван; пустая оценка не должна превращаться в 0/100% | Human review 18 черновиков (Product + Quality) |
| C10 | Автоматическая публикация без подтверждения, расписание публикаций | Планировщик в не-скоупе роадмапа; запрет автопубликации — правило безопасности | Только кнопка «Опубликовать» после предпросмотра |

Не-скоуп роадмапа (Telegram, Instagram, оплата, отмена мероприятия, командные аккаунты, генерация картинок, аналитика) остаётся в силе и здесь не повторяется — `docs/product/roadmap.md` §2.

## 4. Правила изменения скоупа

- Новое требование в спринте → сначала строка в `docs/acceptance.md` («предложено, не принято»), оценка, и только при решении на приёмке — задача в `docs/burndown.md`. Взамен вырезается задача не меньшей оценки.
- Если на приёмке недели 3 (02.12) burndown выше идеальной линии больше чем на 15 ч, следующим режется S9, затем S6 для письма (остаётся страница + ВК).
- S10 (UC-02) не режется: без него Demo Day не показывает подтверждённую боль.
