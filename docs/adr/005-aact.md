# ADR 005: AACT для контроля архитектурных правил

## Статус
Принято

## Контекст
С ростом проекта легко нарушить архитектурные правила: фронтенд начнёт обращаться к БД напрямую, extractor — зависеть от vk-publisher. Это должно ловиться автоматически, а не на ревью.

## Решение
Использовать AACT с правилами в репозитории. Запуск `npx aact check` в CI и локально.

## Альтернативы
- Ручной ревью — медленно, пропускает ошибки.
- ArchUnit — только для Java.
- Свои скрипты — долго писать и поддерживать.

## Последствия
+ Нарушения архитектуры ловятся автоматически.
+ Правила живут в репозитории как код.
+ Можно добавить в CI: PR не смержится с нарушениями.
− Ещё один инструмент в стеке.
− Нужно время на описание правил в конфиге.
