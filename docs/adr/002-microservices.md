# ADR 002: Микросервисная архитектура

## Статус
Принято

## Контекст
Платформа выполняет 4 разные задачи: извлечение данных из анонса, сборка страницы, публикация в VK, отправка email. Каждая использует своё внешнее API (LLM, VK, SMTP) и может масштабироваться независимо.

## Решение
Разделить систему на 4 независимых сервиса: extractor, page-composer, vk-publisher, mailer. Плюс фронтенд apps/site и БД.

## Альтернативы
- Монолит — проще на старте, но сложнее масштабировать и менять отдельные части.
- Два сервиса (extractor+composer и publisher+mailer) — компромисс, но менее гибко.

## Последствия
+ Каждый сервис меняется и деплоится независимо.
+ Узкие места масштабируются точечно.
+ Разные люди работают параллельно.
− Сложнее отладка (запрос идёт через несколько сервисов).
− Больше инфраструктуры: 6 контейнеров вместо 1.
