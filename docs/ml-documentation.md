# AI-часть. Финальная документация

## Рабочие контуры

Delivery из ветки feature/delivery_lab5 предоставляет POST /extract и
возвращает title, date, location, price. Привязка к эксперту, дневной бюджет,
JWT и подтверждение с POST /events находятся в приложении. Ядро Ollama
не записывает карточку и не публикует материалы. По умолчанию используется
qwen2.5:1.5b, резервный тариф — qwen2.5:0.5b. Измерения этой лабораторной
относятся к основному тарифу 1.5B на локальной машине.

Исторический AI API backend/ из лаб 2–4 возвращает расширенную Event и
черновики трёх площадок. Он остаётся источником старых измерений.
Текущий код ядра Delivery находится в services/extractor/llm_logic.py.
ml/final_eval.py загружает этот же файл и передаёт фиксированную дату
каждого примера. При обычном запросе дата берётся по Europe/Moscow.

## Версии

| Версия | Код | Назначение |
|---|---|---|
| lab3-v1 | ml/models/baseline.py | Расширенная Event, Qwen 3B в исходных замерах |
| lab4-v2 / lab4-v2-calendar | ml/prompts_v2/ | Кандидаты промпта и календаря для расширенной Event |
| delivery_before | ml/final_eval.py | Исходный четырёхпольный промпт рабочей Delivery |
| lab5-v3 | services/extractor/llm_logic.py | Дополнительные инструкции и узкие проверки отсутствующих фактов |
| lab5-guarded | services/extractor/llm_logic.py | Выбран исходный промпт Delivery, календарь и проверки отсутствующих значений |

Чтобы вернуть прежний вариант в Delivery, установите
AI_EXTRACTION_VERSION=delivery_before в окружении extractor и пересоздайте
только extractor. Значение lab5-guarded используется по умолчанию.
Значение lab5-v3 включает отклонённый экспериментальный кандидат.
Промпт задаётся сервером. Клиент не выбирает модель или права инструмента.

## Параметры и отказы

POST /api/chat в Ollama, stream=false, format=JSON Schema,
temperature=0, num_ctx=2048, num_predict=256, num_thread=2, keep_alive=0.
Выход проверяется LLMFields с запретом лишних ключей и нечисловых цен.
Дата должна быть ISO local date/datetime. Следом выполняются календарная
подсказка и ограниченные правила finalization, затем повторная валидация.

Delivery сохраняет существующую обработку ошибок и fallback на регулярки.
Бюджет и учёт расхода не меняются этой работой. Данные об ошибках, тарифе,
токенах и trace ID доступны через telemetry.py и мониторинг.
Сравнительный runner измеряет одно обращение без fallback и повторов.
Ошибки сохраняются со status=error, а необъявленные токены не подменяются нулём.

Выход модели требует проверки экспертом. В частности, место или заголовок
могут выглядеть корректно, но не совпадать с исходным текстом.

## Календарь и права

Текущий calendar_hint принимает text и reference_date YYYY-MM-DD.
Возвращает ближайшую ISO дату для одного явного дня недели, включая сегодня,
либо None. Явная числовая дата, несколько дней недели, «следующий» и
контекстные фразы отключают подсказку. При отсутствии данных сохраняется
неопределённость. Функция выполняет только локальное вычисление и не имеет
прав записи, сети, БД или доступа к секретам.

Инструмент прошлой лабы ml.tools.invoke имеет отдельный контракт:
имя resolve_weekday, arguments(reference_date, timezone, weekday), allowlist,
таймаут 200 мс, ответ status(ok/timeout/denied/invalid_input) и date.
Он используется историческим вариантом lab4-v2-calendar. Его таймаут
не следует приписывать локальной функции calendar_hint текущей Delivery.

## Как повторить эксперимент

Из корня репозитория на Python 3.12:

```bash
python -m venv .venv
# Windows CMD: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements-ai.txt
ollama pull qwen2.5:1.5b
ollama serve
```

Последнюю команду оставить работающей в отдельном терминале. Если Ollama
уже запущена, второй сервер не требуется. Для другого локального адреса
задать OLLAMA_BASE_URL. Команды ниже выполняются из корня проекта:

```bash
python -m pytest tests/test_lab5.py -q
python -m ml.final_eval --variants delivery_before final --split dev
python -m ml.final_eval --split all --output docs/experiments/lab5-run
python -m ml.final_scenario
python -m ml.final_report
```

Для прерванного прогона добавить --resume с теми же параметрами. Runner
проверяет SHA-256 кода, датасета, модель и сплит, не принимает старые результаты
при расхождении. После правки кода запускать новый каталог измерений.
Полный прогон отправляет 55 примеров для каждого из пяти вариантов.
Формат, latency, tokens, сырые ответы, флаги постобработки и метрики сохранены
в отдельном каталоге каждого варианта. Документы и ноутбук можно пересобрать
без новых LLM-вызовов командой python -m ml.final_report.

## Методика

Сравниваются общие поля двух контрактов. Исходный датасет и разметка
сохранены без изменений. Исторические метрики пересчитываются в общую
проекцию, а исходные числа лаб 3–4 доступны в прежних отчётах.
needs_context остаётся вне основных знаменателей согласно прошлой методике.
Поиск документов не используется, поэтому метрики retrieval неприменимы.
Результаты одного повтора ограничены вариативностью модели. Перед новой
версией весов требуется повторить весь прогон, зафиксировать digest
и проверить семантику руками. Переименование тега не доказывает идентичность весов.

## Стоимость и границы

Ollama не взимает плату за токены. Количество токенов измеряется из
prompt_eval_count и eval_count, latency — monotonic clock. Электроэнергия
и амортизация не измеряются. Стоимость запроса равна нулю только в смысле
внешнего API-тарифа. API-плата и общий TCO представлены отдельно в отчёте.
Замеры ядра не являются нагрузочным тестом сервера и не измеряют весь путь
браузер → БД → публикация.
